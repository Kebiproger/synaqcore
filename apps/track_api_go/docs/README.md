# Track API (Golang)

## 1. Обзор (Overview)
**Track API** — это высокопроизводительный микросервис на Go, предназначенный для потокового сбора метрик и событий от пользователей (например, клики, просмотры, участие в A/B экспериментах).

**Почему Go?**
Ранее сервис был написан на Python (FastAPI). В системах A/B тестирования трекер — это самая нагруженная часть системы, принимающая тысячи запросов в секунду (RPS). Переписывание на Go позволяет:
- Снизить потребление оперативной памяти.
- Обрабатывать конкурентные HTTP-запросы в разы быстрее благодаря легковесным горутинам.
- Мгновенно прокидывать события в брокер сообщений без блокировки основного потока.

**Стек технологий:**
- **Go** (Golang)
- **Gin** — сверхбыстрый HTTP-фреймворк.
- **RabbitMQ (`amqp091-go`)** — официальный драйвер для публикации сообщений.

## 3. API Эндпоинты (API Reference)

### `POST /track`
Сохраняет событие пользователя и асинхронно отправляет его в RabbitMQ.

**Request Body (application/json):**
```json
{
  "user_id": "uuid-1234-5678",
  "event_name": "button_click",
  "experiment_id": "exp_promo_5",
  "timestamp": 1695800000
}
```

**Responses:**
- `200 OK`: Успешно принято и передано брокеру.
- `400 Bad Request`: Ошибка валидации (отсутствуют обязательные поля или неверный формат).
- `500 Internal Server Error`: Ошибка на стороне сервера (например, RabbitMQ недоступен).

## 4. Интеграция с брокером (RabbitMQ Integration)
Все успешно прошедшие валидацию события публикуются в очередь.
- **Exchange:** (по умолчанию `""` или кастомный, в зависимости от настроек).
- **Routing Key / Queue Name:** `metrics_queue` (или берется из переменной окружения).
- **Формат сообщений:** Сырой JSON (в байтах).

*Примечание:* Соединение с RabbitMQ открывается один раз при старте приложения (`Connection`). Публикация происходит через переиспользуемый `Channel`. При завершении работы приложения соединение закрывается корректно (Graceful Shutdown).

## 5. Переменные окружения (Environment Variables)

Для запуска сервиса необходимы следующие настройки окружения (можно передать через `.env` файл в корне проекта или Docker Compose):

| Переменная | Описание | Значение по умолчанию |
|------------|----------|------------------------|
| `PORT` | Порт, на котором запустится HTTP-сервер | `8000` |
| `RABBITMQ_URL` | DSN для подключения к брокеру | `amqp://guest:guest@localhost:5672/` |
| `GIN_MODE` | Режим работы фреймворка (`debug` или `release`) | `debug` |

## 6. Инструкция по запуску (How to run)

### Локальный запуск (для разработки)
1. Убедитесь, что RabbitMQ запущен (например, через Docker).
2. Загрузите зависимости:
   ```bash
   go mod tidy
   ```
3. Запустите сервис:
   ```bash
   RABBITMQ_URL="amqp://guest:guest@localhost:5672/" go run cmd/api/main.go
   ```

### Запуск через Docker
Сервис будет добавлен в общий `docker-compose.apps.yml`.
Сборка происходит через multi-stage Dockerfile (итоговый образ весит около 15 МБ).
